# CNV AI 保存与采用

CNV AI 保存接受请求 UUID，兼容旧前端 `{requestId, ...}` 对象，但仅提取 UUID；其余客户端结果字段不会持久化。服务端读取完成的加密归档，校验任务、CNV 功能、完成/取消状态、结果功能和当前行 ID，清除 reviewerDecision。缺少行身份的历史记录不按任务 ID 猜测归属，必须重新评估；仍有原输入时可用同任务、同功能的输入行身份验证。

SaaS：写接口先验证任务访问，再验证当前组织 scope 和请求原用户；缺少用户身份拒绝。自部署：有任务编辑权限的协作者可以保存同任务其他用户的结果，不按用户 scope 隔离；任务、位点、功能和状态验证完全保留。

采用 AI 结果时从已保存归档读取建议结论；采用 ClinGen 时服务端重新计算保存的条款，不接受浏览器提交的结论/分数。数据库参考和本地初评仍是用户显式选择的快照，不声称已经完成服务端重新注释。采用时间及操作者由服务器记录；四种来源使用同一并发事务。此修复不更改 Gain/Loss 切换产品行为，不自动修改历史数据。

回归：隔离 PostgreSQL 验证 SaaS 组织/用户限制、自部署同任务协作、跨任务与跨行拒绝、已清除输入且缺少绑定的历史结果拒绝；另验证对象仅作为请求引用及 AI/ClinGen 采用的数据来源。生产部署前仍须解决独立的 adoptedACMG 客户端直接写入问题。
