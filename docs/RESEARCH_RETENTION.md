# 科研定位、迁移与到期销毁

## 部署边界

`DEPLOYMENT_EDITION` 默认为 `opensource`。SaaS 必须显式设置 `saas`，启用 Squid overlay 和 S3/COS 存储。SaaS 在 API、查询与数据库写入层关闭报告及历史检出，并从任务及样本的原始创建时间计算 UTC 720 小时期限。开源版保留报告与历史检出，不安装期限保护规则，也不启动强制清理。

到期访问限制独立于物理清理开关。`RETENTION_CLEANUP_ENABLED=false` 为默认值，仍会停止访问、扫描并记录待清理队列。`RETENTION_BACKUP_POLICY_VERIFIED=true` 是启用清理的发布门槛，必须在下述云端核验完成后设置；该配置本身不是核验证据。

## 发布前只读预检

使用新构建的 Octopus 可执行文件及部署环境运行：

```sh
octopus research-retention-preflight --objects > retention-preflight.json
```

命令不调用迁移，不启动服务或清理工作线程，使用只读、可重复读数据库事务。输出原始创建时间计算的到期记录（含软删除任务）、组织、UUID、对象前缀、历史版本、删除标记、未完成分片和队列指标，不输出样本名称或分析内容。清单包含敏感文件定位信息，仅在受控运维位置保存，核对后销毁。`--at 2026-10-16T00:00:00Z` 可用于预估影响范围；该参数只改变清单截止时刻，不改变在线策略或执行删除。

SQL 回归脚本位于 `scripts/tests/research_retention_sql.py`。与 Squid 源码放在同级目录，生成 SQL 后通过 `psql -X -v ON_ERROR_STOP=1` 执行。所有对象位于 `pg_temp`，事务最终 `ROLLBACK`，覆盖期限不可变、JSON 迁移幂等、到期写入限制、历史受控删除、执行防重建、多租户及租约恢复。不要移除临时命名空间或回滚语句。

先确认 `schema_create_allowed=true`；若为 false，需由数据库管理员授予迁移所需的当前应用 schema 创建权限，无需授予公共 schema 权限。对象清单失败必须解决权限或服务兼容性问题，不得把无法列举版本视为没有版本。制作成功的基线需先验证独立资源副本，不能把任务前缀整体删除当作基线搬迁。

上线前由运维核验并留存不含分析数据的证据：

1. 云数据库自动/手动备份、PITR/WAL、卷与实例快照、旧整库导出、镜像附带数据及异地复制目的地。销毁含到期任务、样本或衍生数据的副本；禁止用整库恢复作为回滚。
2. 对象存储当前/历史版本、复制、对象锁、不可删除保留策略以及未完成分片。服务账户必须能够列举和删除所有任务版本并中止分片；不可删除对象或延迟锁定将阻止上线。
3. 后续备份必须使用严格允许列表，只包含账户、配置、脱敏最小账务。禁止通用 `pg_dump`、数据库快照或整个 Docker 卷备份。允许列表不得包含任务、样本、家系复制内容、结果、附件、加密 AI 请求、操作历史、审计明细或缓存；导出账务时仅选择金额、时间、组织与必要幂等标识，不能 `SELECT *`。
4. FASTQ 仍按上传后七天清理；BAM 按完成后七天和任务期限中较早者处理。BED、独立基线和共享参考资源使用各自策略。独立基线仅保存资源及其可用状态，不保存制作输入或日志。

本次开发时完成了生产只读数据库清点与临时表回滚测试，没有修改生产表或删除线上文件。云端快照、备份与版本策略仍需按上面步骤核验，不能据此宣称物理销毁已完成。

## 发布与命名迁移

1. 暂停任务创建、导入、归档、编辑、异步生成及回调写入，完成预检并核对清单。保留可回滚的代码/镜像，避免包含分析数据的备份。
2. 先升级 Squid，再升级 Octopus（自动进行事务性关注命名迁移和 SaaS 期限回填）。旧字段、JSON 前后状态和投影显式迁移，新字段存在时优先保留新值。旧接口不作在线别名。迁移持有相关表的锁，并仅在迁移事务中暂时关闭操作历史保护规则，失败会回滚。
3. 升级 Python Parquet 查询服务（若部署使用），再升级 YiJian。前端标记接口为 `/focus`、文件标签为 `files`。四种语言和隐私政策版本为 2026-10-14；样本创建确认版本为 `research-identity-v1`。
4. 验证 SaaS 报告/历史 API 禁用、开源功能保留、文件下载、关注不修改判读与证据、到期边界、样本确认及独立基线。恢复写入后观察队列；备份策略核验未完成时保持物理清理关闭。
5. 完成云端核验后设置两个清理配置为 true 并重启 Octopus。启动立即扫描，随后每分钟扫描；队列通过租约、多实例互斥领取和失败重试持续处理。

## 故障与监控

任务先停止访问与写入，再取消所有执行尝试和撤销凭据，清理对象所有版本/分片及服务器缓存，然后清理 Squid 执行详情，最后事务性硬删除 Octopus 关联数据。样本硬删除匹配关系并解除任务/家系关联；独立家系成员保留。任务的期限与分析快照不随样本变化。关注行优先于置顶行，仅写入关注状态和操作记录。

删除失败保留定位信息与 `DESTRUCTION_PENDING` 队列状态，一分钟后重试；租约过期后其他实例可接续。已销毁资源保存不含原始标识的摘要以阻止再创建。账务仅保留必要对账数据，任务名称、文件定位和内容从关联审计与账务描述中清除。

每分钟检查预检输出的 `queue.pending`、`queue.failed`、`queue.leased`、`queue.oldest_due_at`；积压持续增长、失败连续出现或最早待清理时间超过两个扫描周期时告警。失败只代表销毁待完成，不代表已物理删除。检查 `retention: inventory failed` / `retention: destruction pending` 日志并重新列举对应组织前缀；存储权限、云终止或撤销回调失败时继续重试，不得手工删除队列或定位记录。

回滚代码不会恢复已经销毁的数据。到期清单、旧备份清点和验证截图应仅保留必要的脱敏上线证据，不能形成另一份任务数据灾备。
